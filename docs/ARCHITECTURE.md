# Архитектура FlowScore

## Сервисы

| Сервис | Язык | Ответственность |
|---|---|---|
| **Клиенты** | Vue 3 + Pinia, Capacitor | Web, iOS, Android. REST + WebSocket, пуши через FCM/APNs. |
| **API Gateway** | Go (net/http, coder/websocket) | Проверка JWT, rate limiting, маршрутизация, апгрейд до WebSocket, хаб подписок. |
| **User Service** | Go | Регистрация, вход, refresh-токены, профиль, избранное, язык и тема, настройки уведомлений. |
| **Match Service** | Go | Матчи, команды, игроки, события, статистика, история Flow. Владеет схемой матчевых данных. |
| **Ingest Service** | Go | Live-события из внешнего спортивного API, нормализация, публикация в очередь. Отдельные воркеры для погоды и календаря и для реакций болельщиков. |
| **Event Processor / Flow Engine** | Go | Ядро: читает очередь, держит состояние матча в памяти, пересчитывает Flow Momentum, пишет в Redis и Postgres, рассылает обновления. |
| **AI Orchestrator** | Python (FastAPI + gRPC) | Агенты Momentum, Sentiment, Prediction, Explainability. На входе признаки, на выходе скор, вероятности и текст объяснения. |
| **Notification Service** | Go | Правила пользователя, дедупликация, пуши, лента уведомлений. |

## Источники данных

Все источники прячутся за одним Go-интерфейсом `Provider` в Ingest Service. Нормализатор приводит их к единому формату события, и Flow Engine не знает, откуда пришли данные.

| Задача | Источник | Ограничения |
|---|---|---|
| Live топ-5 лиг, полный Flow | ESPN `site.api.espn.com/apis/site/v2/sports/soccer/{eng.1,esp.1,ger.1,ita.1,fra.1}`: `scoreboard`, `summary?event=` (`commentary`, `keyEvents`, `boxscore`) | Неофициальный API, без ключа. Формат может смениться. **xG нет** |
| КПЛ: счёт, события, таблица | API-Football (или Highlightly) | 100 запросов в день, примерно один live-матч КПЛ с опросом раз в минуту |
| Демо, разработка, обучение модели | StatsBomb Open Data: проигрыватель исторических матчей с ускорением ×1…×60 | Исторические данные. Обязательна атрибуция StatsBomb и их логотип |
| Погода | Open-Meteo | Без ключа |

Не используем SofaScore и FotMob: у них нет публичного API, сбор данных запрещён правилами, запросы блокируются.

**Хранилища и шина:** PostgreSQL (источник правды), Redis (кэш и pub/sub между инстансами), Kafka или NATS (шина событий), Prometheus + Grafana.

## Go-паттерны

- **Актор на матч:** у каждого live-матча своя горутина, и только она владеет его состоянием, поэтому мьютексы не нужны.
- **Конвейер на каналах:** сырые события → нормализованные → признаки → обновления Flow. Буферизованные каналы дают backpressure.
- **Fan-out / fan-in:** запись в БД, пересчёт Flow и запрос к AI идут параллельно через `errgroup.WithContext`.
- **Context:** контекст тянется от HTTP до gRPC. Таймаут AI 300 мс, после него отдаём последний Flow из Redis.
- **WebSocket-хаб:** шардирован по `match_id`, у каждого соединения своя горутина записи. Если буфер переполнен, соединение отключается.
- **select + ticker:** события, тик пересчёта раз в 5 с, ответы AI, `ctx.Done()`.
- **Graceful shutdown:** по SIGTERM прекращаем приём, ждём, пока опустеют каналы, и сбрасываем Flow в БД.
- Плюс `singleflight`, `sync/atomic`, пул и батчи pgx, `sqlc`, `pprof`.

## Жизненный цикл

1. **Вход:** хеш argon2, access-токен на 15 мин (хранится в памяти), refresh на 30 дней (в защищённом хранилище). Тихое обновление access, при истёкшем refresh — модалка «Сессия истекла».
2. **Главная:** список матчей (Redis, при промахе Postgres) плюс WS на общий live-канал.
3. **Матч:** матч, история Flow и события одним пакетом, затем WS `/ws/matches/:id/stream`. Путь события: Ingest → актор (окна 1/5/15 мин, Flow) → параллельно gRPC в AI → Redis сразу, Postgres пачкой → Redis pub/sub → Gateway → клиент. От удара до экрана около 1 с. Если AI опаздывает, Flow уходит без объяснения, текст приходит следующим сообщением.
4. **«Что, если…?»:** сценарий уходит в AI Orchestrator, обратно приходят контрфактические вероятности и прогноз потока. Сценарий и результат сохраняются.
5. **Уведомления:** скачок Flow → подписчики из Redis (избранное и порог) → тихие часы и дедупликация → FCM. Если приложение открыто, вместо пуша показывается баннер в интерфейсе.
6. **После матча:** актор останавливается, финальные значения уходят в Postgres, кэш инвалидируется. Ночная джоба кладёт признаки в feature store.
7. **Админка:** пересчёт или бэкфилл через очередь и пул воркеров, переключение версии модели без перезапуска.

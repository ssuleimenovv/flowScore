# Своя модель xG: спецификация

xG (expected goals) — вероятность того, что удар станет голом. StatsBomb отдаёт свой xG к каждому удару, а у live-источников вроде ESPN его нет: есть только координаты удара и его описание. Своя модель считает xG из того, что есть в любом фиде. В хронике матча она стоит рядом с xG StatsBomb: «xG 0.08 · наша 0.11».

Код в `ai/xg/`, модель для Go лежит в `ai/xg/model.json`, результат последнего прогона — в `ai/xg/report.json`. Go считает xG сам (`services/internal/xg`), без Python-сервиса.

## 1. Модель

Логистическая регрессия:

```
xG = 1 / (1 + e^−z),   z = a + b_distance·distance + b_angle·angle + b_header·header + b_situation
```

| Признак | Что значит |
|---|---|
| `distance` | ярды от точки удара до центра ворот |
| `angle` | угол между линиями к двум штангам, в радианах: насколько широкими ворота видны с точки удара |
| `header` | 1 для удара головой |
| `set_piece` | 1, если владение началось с углового или штрафного |
| `free_kick` | 1 для прямого удара со штрафного |
| `penalty` | 1 для пенальти |

Игра с ходу — базовый уровень: все три признака ситуации равны нулю.

**Координаты** — ярды поля StatsBomb, 120 × 80. Ворота, по которым бьют, стоят на линии x = 120, штанги на y = 36 и y = 44. Угол считается как `atan2(8·dx, dx² + dy² − 16)`, где `dx = 120 − x`, `dy = y − 40`. `atan2` вместо `atan` нужен, чтобы угол не переворачивался у самой лицевой линии, где знаменатель отрицательный.

Позиция события в API — шкала 0–100 по обеим осям. Publisher переводит её обратно в ярды (`x / 100 · 120`, `y / 100 · 80`) перед тем, как спросить модель.

## 2. Параметры v1

Обучены на всём сезоне, 9 908 ударов.

| Параметр | Значение | Смысл |
|---|---|---|
| `a` | −0.771 | |
| `distance` | −0.111 | каждый ярд дальше: шансы (odds) × 0.89 |
| `angle` | +1.188 | ворота видны шире: шансов больше |
| `header` | −0.993 | головой шансы в 2.7 раза ниже, чем ногой с той же точки |
| `set_piece` | −0.483 | после стандарта удары чаще из толкучки: шансы × 0.62 |
| `free_kick` | +0.852 | прямой штрафной опаснее удара из игры с той же точки |
| `penalty` | +2.803 | пенальти: xG 0.81 |

Пенальти модель оценивает в 0.812. В сезоне забили 74 из 91 (0.813). У StatsBomb 0.78.

## 3. Проверка на сезоне

**Данные.** АПЛ 2015/16 из StatsBomb Open Data: 380 матчей, 9 908 ударов, 988 голов (`ai/xg/shots.py`). xG StatsBomb в обучение не входит, это эталон для сравнения.

**Как проверяли.** Так же, как Flow и модель исхода: 5 блоков сезона по датам, каждый блок предсказывает модель, обученная на остальных четырёх. Удары одного матча похожи друг на друга, поэтому случайное разбиение подсмотрело бы в тот же матч. Интервал разницы со StatsBomb — бутстрэп по матчам (1000 выборок).

| Модель | log loss | Brier | AUC |
|---|---|---|---|
| константа (доля голов, 10%) | 0.3245 | 0.0898 | 0.500 |
| **наша модель v1** | **0.2723** | **0.0768** | **0.774** |
| xG StatsBomb | 0.2550 | 0.0712 | 0.809 |

**Калибровка** — удары, разбитые на 10 равных групп по предсказанному xG (около 990 в каждой): средний прогноз группы и доля её ударов, ставших голами.

| Прогноз | 0.014 | 0.025 | 0.035 | 0.046 | 0.059 | 0.073 | 0.092 | 0.118 | 0.165 | 0.371 |
|---|---|---|---|---|---|---|---|---|---|---|
| Забито | 0.019 | 0.025 | 0.029 | 0.035 | 0.053 | 0.068 | 0.116 | 0.131 | 0.156 | 0.363 |

**Выводы.**
- **StatsBomb лучше, и это ожидаемо.** Разница в log loss 95% [0.0135, 0.0212] в их пользу. Их модель видит freeze frame: где стоят вратарь и защитники в момент удара. Наша видит только точку удара и то, что к нему привело.
- **Наша модель проходит 75% пути от константы до StatsBomb** по log loss, используя только то, что есть в любом live-фиде.
- **Модель откалибрована:** когда она говорит «16%», забивают около 16%. Это важнее AUC, потому что xG складывается в сумму за матч.
- **Сложнее не лучше.** `log(distance)` и взаимодействие «голова × дистанция» не изменили log loss (0.2722–0.2725). Осталась простая модель: шесть весов, одна формула в Go.

**Оговорки.**
- Один сезон одной лиги.
- Ситуации размечены по полям StatsBomb (`shot.type`, `play_pattern`). У другого источника разметку придётся сопоставить с теми же четырьмя категориями, иначе модель получит не те признаки, на которых училась.

## 4. Go и Python

`ai/xg/golden.py` считает xG по `model.json` для 200 ударов сезона и шести граничных случаев (пенальти, удар с лицевой линии, с центра поля, головой после углового, штрафной) и пишет их в `services/internal/xg/testdata/golden.json`. Go-тест считает те же удары с тем же `model.json`: наибольшая разница 8·10⁻¹⁷. Второй тест проверяет здравый смысл: вблизи xG выше, чем издали, по центру выше, чем сбоку, ногой выше, чем головой, пенальти около 0.8.

Маппер StatsBomb (`services/internal/provider/statsbomb`) размечает ситуацию удара той же логикой, что `shots.py`. Табличный тест в `mapper_test.go` закрепляет эту разметку.

**Как повторить.** `python ai/calibration/download.py`, затем `python ai/xg/shots.py`, `python ai/xg/fit.py` (несколько секунд) и `python ai/xg/golden.py`.

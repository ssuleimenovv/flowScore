# FRONTEND.md — правила фронтенда FlowScore

Эти правила обязательны. Отступление от них считается багом.

## 1. Источник истины — мокап

Мокап лежит в `design/mockup/` (исходник: канвас FlowScore на claude.ai, 47 артбордов, у каждого экрана тёмная и светлая версии). Всё, что на экране, берётся из него.

| Борд | Что из него берём |
|---|---|
| **Токены** | Цвета, шкала текста, радиусы, отступы, брейкпоинты. Только CSS-переменные `--fs-*`, никаких значений «на глаз». |
| **Desktop** и **Mobile · iOS** | Разметка, иерархия, состав блоков. Ничего не добавляем и не выкидываем без обсуждения. |
| **Состояния** | Для каждого экрана обязательны: загрузка (скелетон), пусто, ошибка, offline, обрыв WebSocket. Пока нет всех пяти, экран не готов. |
| **Экраны и эндпоинты** | Маршруты фронта и запросы к бэкенду ровно такие, как на борде. |

### Шрифты
- **Onest** (400–700) — интерфейс.
- **JetBrains Mono** (500–600) — минуты, коды, метрики.
- **Big Shoulders Display** (800) — только табло и Flow. Кириллицы в нём нет.

## 2. Стек

Vue 3 + Pinia, мобильная оболочка Capacitor (iOS и Android). REST + WebSocket, пуши через FCM/APNs.

## 3. Анимации и плавность

Плавность нужна везде. Библиотеки используем активно, каждую для своей задачи:

| Библиотека | Для чего |
|---|---|
| **Lenis** | Плавный скролл. Работает от тикера GSAP (`gsap.ticker`), а не от своего rAF. Обязательно синхронизирован с ScrollTrigger. |
| **GSAP + ScrollTrigger** | Появление секций, счётчики цифр, рост баров на графиках, закрепление шапки матча при прокрутке, переходы между экранами. |
| **Rive** | Логотип, лоадеры, анимация гола и скачка Flow, иконки состояний. |
| **Three.js** | Отдельные 3D-блоки: волна потока и тепловая карта поля. Грузятся лениво и никогда не стоят на первом экране. |

- Основная кривая: `cubic-bezier(0.2, 0.7, 0.2, 1)`. У ползунка переключателя своя: `cubic-bezier(0.3, 0.7, 0.3, 1)`.
- Длительности взяты из мокапа, каждая заведена токеном `--fs-duration-*`. Других значений нет.

| Токен | мс | Где в мокапе |
|---|---|---|
| `press` | 140 | нажатие кнопки, `scale(0.96)` |
| `fade` | 150 | прозрачность ссылок и баров |
| `color` | 200 | фон и яркость при наведении |
| `toggle` | 220 | переключатель, сегменты |
| `nudge` | 250 | сдвиг стрелки при наведении |
| `lift` | 300 | подъём карточки |
| `grow` | 500 | ширина полос, зум фото |
| `enter` | 700 | появление секций |
| `bar` | 800 | рост вертикальных баров |
| `bar-h` | 900 | рост горизонтальных баров |
| `count` | 1200 | счётчики цифр |
| `spin` | 900 | спиннер, цикл |
| `skeleton` | 1400 | пульс скелетона, цикл |
| `pulse` | 1600 | пульс live-точки, цикл |
| `marquee` | 38000 | бегущая строка, цикл |
| `stagger` | 60 | шаг задержки между элементами списка |

### Lenis только на десктопе
В Capacitor-оболочке Lenis ломает нативный инерционный скролл iOS, перехватывает pull-to-refresh и мешает жесту «назад», а это нарушает Apple HIG. На мобильных скролл нативный, плавность даём через переходы GSAP и Rive.

### prefers-reduced-motion
При «Уменьшить движение» Lenis выключен, GSAP и Rive сразу показывают конечное состояние без анимации.

## 4. Apple Design — главный ориентир

Из скиллов по фронту главный `apple-design`, остальные (`impeccable`, `taste-skill`, `dataviz`) ему подчиняются.

- Safe areas через `env(safe-area-inset-*)`.
- Таб-бар 49 pt + 34 pt (home indicator). Навбар 44 pt с крупным заголовком.
- Тач-цели не меньше 44 pt.
- Сгруппированные списки: строки от 44 pt, разделители 0.5 pt.
- Полупрозрачные бары с blur.
- Переключатели 51×31, сегментированные контролы.
- Поддержка Dynamic Type обязательна.

## 5. Порядок работы

1. Токены и тема
2. Шрифты
3. Каркас layout с навигацией
4. Компоненты состояний

## 6. Проверка

Каждый PR сверяется с бордом: скриншот реализации рядом со скриншотом артборда. Расхождение в токенах, размере шрифта или отступах считается багом, а не мелочью.
